# Alembic Migrations Setup

`init_db()` (create_all) is fine for first setup, but real projects use **Alembic**
for versioned schema changes — so you can evolve the schema safely over time and
roll back if needed. Here's how to initialize it for this project.

## One-time setup
```bash
pip install alembic
cd database
alembic init migrations
```

Then edit `migrations/env.py`:
1. Import your models' Base:  `from models import Base`
2. Set:  `target_metadata = Base.metadata`
3. Point the URL at your env var (in alembic.ini or env.py):
   `sqlalchemy.url = ` (leave blank) and in env.py read `os.getenv("DATABASE_URL")`

## Generate the first migration (autogenerated from your models)
```bash
alembic revision --autogenerate -m "initial schema"
```

## Apply migrations
```bash
alembic upgrade head
```

## Later schema changes
Edit `models.py`, then:
```bash
alembic revision --autogenerate -m "describe change"
alembic upgrade head
```

## Why this matters
Interviewers look for this: `create_all` can't evolve a live database without
losing data. Alembic tracks each change as a versioned, reversible migration —
the professional way to manage schema over a project's life.
